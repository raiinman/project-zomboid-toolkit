# Purpose

Keep architecture, acceptance criteria, operating instructions, and provenance
accurate enough to continue the project without conversation history.

## Ownership

`design.md` owns requirements and decisions. `plan.md` owns ordered delivery and
acceptance checks. `skills.md` owns skill/framework provenance and usage evidence.
`research.md` owns the four requested internet research passes, source classes,
build applicability, local corroboration, and unresolved compatibility gaps.
`wiki-research.md` and `wiki-coverage.csv` own the four wiki passes and explicit
page review depths. `validation.md` owns measured implementation/startup evidence.

## Local Contracts

- Label planned, implemented, offline-tested, and game-tested behavior distinctly.
- Record assumptions and compatibility gaps without claiming live validation.
- Distinguish official API signatures, official release history, community event
  explanations, and local shipped-source evidence when documenting game behavior.
- Keep game source references local/read-only and out of the repository.
- Preserve `DOX-LICENSE` with the adapted DOX framework.
- Keep fetched, article-reviewed, index-reviewed, selected-section and excluded
  coverage distinct. A page count never implies exhaustive descendant coverage.

## Work Guidance

Use concise instructions, stable contracts, and links to primary sources.

## Verification

Check documented commands against CLI help and repository configuration. Check
local links resolve before closeout.
